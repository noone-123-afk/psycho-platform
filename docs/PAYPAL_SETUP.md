# إعداد PayPal وWebhooks

يستخدم المشروع Node.js/Express وMongoDB ومكتبة `@paypal/checkout-server-sdk`. لا تنشئ إعدادات Python/FastAPI أو جداول PostgreSQL لهذا التكامل.

## قبل الإعداد

1. أنشئ حساب PayPal Business وأكمل متطلبات التحقق لدى PayPal.
2. اختبر أولاً باستخدام تطبيق وحسابات Sandbox.
3. لا تستخدم المدفوعات الحقيقية إلا بعد مراجعة السعر وسياسة الاسترداد والتسليم والدعم والمتطلبات القانونية في الأسواق المستهدفة.

## إعداد Sandbox

1. أنشئ تطبيقاً في PayPal Developer Dashboard ضمن Sandbox.
2. خزّن `PAYPAL_CLIENT_ID` و`PAYPAL_CLIENT_SECRET` في إعدادات البيئة السرية لخادم Render، واضبط `PAYPAL_ENV=sandbox`.
3. أنشئ Webhook في التطبيق نفسه بعنوان:

   `https://<backend-host>/api/webhooks/paypal`

4. اشترك في الأحداث:
   - `CHECKOUT.ORDER.APPROVED`
   - `PAYMENT.CAPTURE.COMPLETED`
   - `PAYMENT.CAPTURE.DENIED`
   - `PAYMENT.CAPTURE.REFUNDED`
5. خزّن Webhook ID في `PAYPAL_WEBHOOK_ID` على Render. يجب أن يطابق Webhook التطبيق والبيئة نفسهما المستخدمين في بيانات الاعتماد.
6. أرسل حدث اختبار من لوحة PayPal، ثم تحقق من استجابة endpoint وسجل MongoDB. لا ترسل أسراراً أو بيانات مشترين حقيقية إلى سجلات الاختبار.

## إعداد Live

بعد نجاح Sandbox ومراجعة الإطلاق:

1. أنشئ/اختر تطبيق Live في لوحة مطور PayPal.
2. ضع بيانات Live فقط في إعدادات Render:
   - `PAYPAL_ENV=live`
   - `PAYPAL_CLIENT_ID`
   - `PAYPAL_CLIENT_SECRET`
   - `PAYPAL_WEBHOOK_ID`
3. أنشئ Webhook Live على عنوان الخادم الإنتاجي نفسه وبالأحداث المذكورة أعلاه.
4. أعد تشغيل/نشر الخادم، وتحقق من `/api/health` ثم نفّذ معاملة حقيقية منخفضة القيمة فقط بعد الموافقة. اتبع سياسة الاسترداد يدوياً بعد التحقق.

لا تضع `PAYPAL_CLIENT_SECRET` أو ملف `.env.production` في Git أو Vercel. عنوان API يختاره SDK من `PAYPAL_ENV`؛ لا يحتاج المشروع إلى `PAYPAL_MODE` أو `PAYPAL_API_BASE`.

## المعالجة والحدود الحالية

- يتحقق الخادم من التوقيع مع PayPal قبل قبول أي حدث، في Sandbox وLive. يحتاج ذلك إلى بيانات الاعتماد و`PAYPAL_WEBHOOK_ID`.
- تُحفظ بيانات وصفية محدودة للحدث في مجموعة MongoDB `webhookevents`، مع معرّف فريد لمنع معالجة الحدث المكرر وانتهاء السجلات بعد سنة. لا يُحفظ جسم الحدث كاملاً.
- حدث `PAYMENT.CAPTURE.COMPLETED` لا يعلّم التقييم مدفوعاً إلا بعد مطابقة الطلب مع سجل التقييم، ثم استعلام PayPal عن الطلب والتحقق من حالته ومعرّف التقييم والمبلغ والعملة ومعرّف الالتقاط.
- إشعار الموافقة، والرفض، والاسترداد يُسجل، لكنه لا يغيّر حالة الدفع تلقائياً. لا تنفذ المنصة حالياً استرداد الأموال أو إلغاء التسليم آلياً عند الاسترداد؛ راجع هذه الأحداث يدوياً.
- لا يُنشئ Webhook التقرير ولا يرسله بالبريد. يواصل المستخدم تدفق الالتقاط الحالي، أو يعيد محاولة تسليم تقرير مدفوع من التطبيق.
- إذا تعذر التحقق أو تعذر الوصول إلى PayPal/MongoDB، يعيد endpoint خطأً قابلاً لإعادة المحاولة من PayPal. الأحداث المسجلة كمعالجة أو متجاهلة تُقرّ دون إعادة تنفيذ.

## التشخيص

- `400`: جسم غير صالح أو توقيع غير صحيح؛ تأكد من URL وWebhook ID والبيئة.
- `503`: تحقق PayPal أو التخزين/المعالجة غير متاح؛ افحص سجل الخادم ولوحة PayPal لإعادات الإرسال.
- لا تسجّل مفاتيح PayPal أو جسم Webhook أو بيانات المشتري في سجلات التطبيق.
